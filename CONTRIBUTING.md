# Contributing to The RPG Blend

## Purpose

The RPG Blend exists to document practical IBM i engineering, responsible modernization, operational discipline, developer education, and technical leadership.

Contributions should improve clarity, accuracy, operational realism, and technical credibility.

## Before Contributing

- Use an issue template to propose substantial new content before investing in a large pull request.
- Confirm that the material is original or that you have the right to contribute it.
- Do not submit confidential, proprietary, personal, customer, patient, employee, candidate, or production information.
- Do not include credentials, private system identifiers, internal screenshots, or code that you are not authorized to publish.
- Identify third-party material and its license before including it.

Acceptance of a contribution does not create a new repository-wide open-source or Creative Commons license. `COPYRIGHT_AND_REUSE.md` remains the governing reuse policy unless a file or directory explicitly states otherwise.

## Contribution Standards

Good contributions are:

- Practical
- Specific
- Experience-driven
- Operationally grounded
- Technically accurate
- Maintainable
- Safe to publish
- Consistent with The RPG Blend brand and editorial standards

Avoid:

- Buzzword-heavy writing
- Vendor marketing language
- Generic AI-generated filler
- Hype-driven modernization claims
- Unrealistic architecture proposals
- Unvalidated commands or code presented as proven
- Broad rewrites that ignore the repository taxonomy

## Preferred Topics

- IBM i modernization
- Modern RPG
- Db2 for i and SQL engineering
- Stored procedures and service boundaries
- Service programs and APIs
- Production support and troubleshooting
- Operational governance and release management
- AI-assisted development and adoption
- Developer education and mentoring
- Engineering leadership and delivery systems

## Writing Expectations

Preferred characteristics:

- Clear headings and short paragraphs
- Strong operational context
- Real enterprise examples that are safe to publish
- Explicit risks and trade-offs
- Primary-source validation for release-sensitive technical claims
- Leadership perspective where appropriate

Use the templates in `/templates` and follow `PUBLISHING_STANDARD.md`.

## Repository Workflow

1. Open or reference an issue.
2. Create a focused branch.
3. Place the change in the canonical directory and naming structure.
4. Update related indexes, links, standards, or source registers when needed.
5. Open a pull request using the repository template.
6. Resolve review conversations before squash merging.

Do not commit directly to `main`.

## Pull Request Expectations

A pull request should explain:

- What changed
- Why it belongs in The RPG Blend
- What technical or editorial validation was performed
- Whether any claims remain unvalidated
- Whether public links, screenshots, code, or third-party material were added
- Which related issues it resolves or advances

## Philosophy

The RPG Blend prioritizes:

- Clarity over hype
- Maintainability over cleverness
- Operational discipline over chaos
- Modernization with realistic governance
- Long-term system stewardship
- Human accountability for AI-assisted work
