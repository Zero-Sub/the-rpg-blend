# The RPG Blend Site Strategy

**Last aligned:** August 5, 2026

## Purpose

The public site is the durable presentation layer for The RPG Blend™, The RPG Blend Publishing, The RPG Blend Academy, George VanEaton's articles, books, frameworks, and educational work.

The site is not developed in this public content repository.

## Repository Roles

| Repository or system | Role |
|---|---|
| `Zero-Sub/the-rpg-blend` | Public canonical source for approved articles, frameworks, Academy source, standards, and reusable brand copy |
| `Zero-Sub/the-rpg-blend-site` | Private website-development repository for layouts, components, routes, metadata, deployment configuration, and prelaunch work |
| Google Drive | Working documents, manuscripts, research, review files, and collaboration |
| The RPG Blend Studio / George OS | Planning, workflow, status, editorial queue, and orchestration |

Unfinished website work must remain in the private site repository. Approved public content should be promoted into this repository before or alongside publication.

## Website Stack

- Astro
- Markdown-first content
- Static generation
- Vercel hosting
- Custom domain at launch

GitHub Pages is not the selected deployment model.

## Channel Roles

| Channel | Role |
|---|---|
| The RPG Blend website | Durable public archive, brand home, book pages, Academy positioning, and professional presentation |
| Substack | Long-form publication, subscriber communication, and email distribution |
| LinkedIn | Professional reach, discussion, article amplification, and executive visibility |
| GitHub | Versioned public technical source, standards, examples, and educational material |

## Publishing Flow

```text
Working draft and research
        |
Editorial and technical review
        |
Approved canonical content in this repository
        |
Website adaptation in the private site repository
        |
Substack and LinkedIn distribution
        |
Links and publication status recorded in the canonical workflow
```

Publication-channel adaptations may vary in length and presentation, but they must preserve the approved argument, brand language, technical accuracy, and legal boundaries.

## Privacy and Security Boundary

The public site and this repository must not contain:

- Credentials or tokens
- Private system addresses
- Customer or patient information
- Employee or candidate information
- Private leadership notes
- Personal health or family information
- Production screenshots or proprietary code without explicit approval

## Long-Term Goal

Build a respected engineering publication, modernization reference library, publishing platform, and educational destination for enterprise IBM i professionals.
