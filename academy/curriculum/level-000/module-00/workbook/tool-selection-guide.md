# Module 0 Quick Guide — Which Tool Should I Use?

**Core principle:** Technology follows the problem.

| I need to… | Start with… | Why |
|---|---|---|
| Edit RPG/CL or browse IBM i development objects | VS Code + Code for IBM i | Academy development home base |
| Run SQL during normal development | Db2 for i extension when practical | Keeps SQL close to the development workflow |
| Use Run SQL Scripts or richer database tooling | IBM i Access Client Solutions | Mature SQL/database capabilities |
| Use a 5250 session | IBM i Access Client Solutions | Appropriate emulator/tooling path |
| View/manage spooled files or perform data transfer | IBM i Access Client Solutions | Appropriate operational utility |
| Use approved browser-based system views | IBM Navigator for i | Operational/admin observation |
| Investigate an existing performance symptom | Start with approved evidence; involve PDI/Collection Services/Job Watcher/Disk Watcher/SQL performance tools as appropriate | Performance work is evidence-driven and may require elevated authority |
| Explain unfamiliar IBM i code with AI | Approved AI assistant; IBM Bob when available | Assistance with understanding/review, not final authority |
| Support an older workflow using PDM/SEU/STRSQL/RDi | Recognize the existing tool and translate the task into the approved team workflow when appropriate | Legacy interoperability matters; legacy does not automatically mean wrong |

## Three questions before choosing a tool

1. What problem am I solving?
2. What evidence or change do I actually need?
3. What tool is approved and least risky for that task?

## Remember

- VS Code is home base, not the only valid IBM i tool.
- Seeing an operational tool does not authorize changing its settings.
- AI assistance does not replace verification, testing, review, security, or engineering judgment.
